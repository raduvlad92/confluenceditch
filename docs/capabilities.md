# Capability matrix

Status is based on fixtures and one explicitly authorized narrow live Cloud test: two selected current published pages and one 346-byte text attachment were captured and independently verified after download. This is not a public capability or whole-space completeness claim. Data Center and Server are unimplemented.

| Capability | Local P0 evidence | Live/customer gate |
| --- | --- | --- |
| Destination-independent archive | Normalized fixture → ordinary files, no Notion connection | Private durable capture and authorized download |
| Pages and blog posts | Namespaced identity; current published pages tested live; blog posts fixture-only | Broader live pagination and customer-like source permission fixtures |
| Global/personal spaces | Supplied selected-space metadata and navigation | Observable inventory of both space types |
| Source revisions | Supplied actual bodies, explicit missing records and history navigation | Exhausted version discovery, pinned retrieval and drift reconciliation |
| Original evidence | Exact storage XHTML and selected-resource API JSON tested live | Native uploaded packages and durable raw-object storage |
| Attachment bytes | One current text attachment verified live; hashes, local bytes and exact fixture equality | Historical/resumable transfer and larger byte-volume proofs |
| Authorship | Separate nullable creator/owner/editor/revision-author fields | Live profile/status retrieval and identity reconciliation |
| Membership and permission evidence | Preserve supplied raw JSON, observation times and explicit gaps | Source collection, inheritance semantics and no-access-broadening tests |
| Markdown | Fragment, code/CDATA, Unicode, lists/tasks, simple tables | Full PRD fixture suite and tested reader matrix |
| Unsupported structures | Macro parameters/bodies, table/layout fallbacks, structured findings | Representative vendor/app fixtures and reviewed fidelity |
| Links/navigation | Pre-inventoried current page identities, exact asset bindings, explicit Unicode anchors, unresolved findings | Broader source URL/anchor variants and reader compatibility |
| Integrity | File hashes/counts, declared links/anchors, independent disk read-back | Network-disabled reader inspection and package-part reconciliation |
| Reprocessing | Rebuild supplied normalized input with a converter version | Rebuild from durable original source payloads without reacquisition |
| Worker compatibility | Browser-target bundle without Node core dependencies | Actual Workers/Workflows/Queues execution and limits |
| Organization isolation | Organization ID in the artifact only | Server-side archive grants, cross-tenant tests and audited administration |
| Capture lifecycle/recovery | None; local generation only | Neon state/checkpoints, generation fencing, R2 references and joint restore |
| Downloads | Local directories and browser ZIP; session-gated app gateway and disconnect revocation tests | Production archive entitlements; distinct current/full packages; multipart ZIP |
| Native upload formats | None; normalized fixture JSON only | Choose real supported export samples; traversal/decompression tests |
| Source connection | Local API-token connection, scoped gateway, in-memory credentials and two-hour session | Distributable OAuth, encrypted durable credentials, organization grants |
| Recurring capture, billing, destination delivery, governed/AI access | Unimplemented in the archive product | Respective PRD release gates |

The earlier Notion UI, OAuth and BullMQ code are prototype code, not evidence that these archive product gates have passed. Source authors and preserved policies never grant archive access. The local builder deliberately implements no hosted authorization or provider calls.
